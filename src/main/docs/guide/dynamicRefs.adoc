JSON Schema 2020-12 introduces the `$dynamicAnchor` and `$dynamicRef` keywords, which resolve a reference through the *dynamic scope* at the point of use rather than at the point of definition (see the https://json-schema.org/draft/2020-12/json-schema-core#section-7.1[specification, window="_blank"]).

This is useful for recursive type hierarchies: a base type that references itself in one of its properties can be subtyped, and the recursive property should resolve to the *active subtype*, not back to the base.

For example, given:

[source,java]
----
class BaseCategory {
    public List<BaseCategory> children;
}

class LocalizedCategory extends BaseCategory {
    public String displayName;
    public String locale;
}
----

By default Micronaut OpenAPI emits a static self-reference for `children`:

[source,yaml]
----
BaseCategory:
  type: object
  properties:
    children:
      type: array
      items:
        $ref: '#/components/schemas/BaseCategory'
----

So any subtype inherits `children` typed as `BaseCategory[]`, even when validating a `LocalizedCategory`.

== Enabling dynamic references

Set the `micronaut.openapi.schema.dynamic-refs.enabled` property to `true`.

NOTE: Dynamic references require an https://json-schema.org/draft/2020-12/json-schema-core[OpenAPI 3.1, window="_blank"] document. The flag is ignored when generating an OpenAPI 3.0 document.

By system property:

[source,commandline]
----
-Dmicronaut.openapi.openapi31.enabled=true -Dmicronaut.openapi.schema.dynamic-refs.enabled=true
----

or in `openapi.properties`:

[source,properties]
----
micronaut.openapi.openapi31.enabled=true
micronaut.openapi.schema.dynamic-refs.enabled=true
----

or in `application.yml`:

[configuration]
----
micronaut:
  openapi:
    openapi31:
      enabled: true
    schema:
      dynamic-refs:
        enabled: true
----

With the flag enabled, the same types produce:

[source,yaml]
----
BaseCategory:
  $dynamicAnchor: BaseCategory
  type: object
  properties:
    children:
      type: array
      items:
        $dynamicRef: '#BaseCategory'
LocalizedCategory:
  $dynamicAnchor: BaseCategory
  type: object
  allOf:
    - $ref: '#/components/schemas/BaseCategory'
    - type: object
      properties:
        displayName:
          type: string
        locale:
          type: string
----

The base type and every subtype declare the same `$dynamicAnchor`, and the recursive property emits a `$dynamicRef`. A consumer that understands dynamic scope (for example, a validator or SDK generator) then resolves `children` to `LocalizedCategory` when operating on `LocalizedCategory`.

== Generic types

Dynamic-refs mode also collapses single-variable generic wrappers into one reusable template plus inline `$defs` bindings, instead of duplicating a concrete schema per type argument. Given:

[source,java]
----
class Response<T> {
    public T data;
}

class Page<T> {
    public List<T> items;
    public int total;
}
----

used as `Response<Pet>`, `Response<Group>`, and `Page<Pet>`, the default mode produces a concrete schema per binding (`Response_Pet_`, `Response_Group_`, `Page_Pet_`). With dynamic-refs enabled, a single template is emitted per generic and each usage site gets an inline binding:

[source,yaml]
----
components:
  schemas:
    Response:                  # one template, defined once
      $dynamicAnchor: dataType
      properties:
        data:
          $dynamicRef: '#dataType'
      $defs:
        dataType:
          $dynamicAnchor: dataType
          not: {}
    Page:
      $dynamicAnchor: itemType
      properties:
        items:
          type: array
          items:
            $dynamicRef: '#itemType'
        total:
          type: integer
      $defs:
        itemType:
          $dynamicAnchor: itemType
          not: {}
paths:
  /pet:
    get:
      responses:
        '200':
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/Response'
                $defs:
                  dataType:
                    $dynamicAnchor: dataType
                    $ref: '#/components/schemas/Pet'
----

The template declares a `$dynamicAnchor` (named after the variable's role: `itemType` when used as a collection/array element, `dataType` otherwise) and a `$defs` placeholder (`$dynamicAnchor` + `not: {}`) marking the unbound slot; the variable's usages become `$dynamicRef` consumers. Each binding re-declares the anchor via an inline `$defs` entry pointing at the concrete type. Dynamic-scope resolution then switches the slot to the bound type at the point of use, while the wrapper instance validates against the template only.

NOTE: swagger-core's `Schema` model does not expose a `$defs` field. Micronaut OpenAPI attaches `$defs` via a reflective workaround on the schema's extensions map (which the serializer emits verbatim). This is temporary and is replaced automatically by native `$defs` support once a future swagger-core ships it.

== Anchor naming and limitations

* The anchor name is derived from the recursive base type's schema name (for example `BaseCategory`), or from the generic type variable's role (`itemType` for collection/array elements, `dataType` for scalar fields). If the name is not a valid JSON Schema anchor, Micronaut OpenAPI sanitizes it by replacing invalid characters with `_` and prefixing `_` when the name does not start with a valid anchor character. For example, schema name `2024 v1:Category` becomes anchor `_2024_v1_Category`.
* For recursive types, the base type and all of its subtypes share the same anchor.
* A single schema can carry only one `$dynamicAnchor`. As a result, if a recursive subtype introduces a *different* recursive property of its own, the inherited anchor takes precedence and the subtype's own recursion keeps a normal `$ref`. This edge case may be revisited in a future release.
* Generic-template preservation currently applies to single-parameter generics used directly (for example as a controller return type or field) where the type argument is a reference type. Cases that keep their default concrete schemas include: multi-parameter generics (`Map<K, V>`), a concrete argument that is a primitive, array, collection or map (for example `Response<String>`), generics annotated with `@Schema`, named subtypes (for example `class PetResponse extends Response<Pet>`), nested parameterized bindings (for example `Response<Page<Pet>>`), and self-referential generics (for example `class Tree<T> { List<Tree<T>> children; }`, which is handled by the recursive path instead). A template is not independently usable on its own (its unbound slot validates nothing); it is meaningful only at a binding site.
* Outside dynamic-refs mode (the default), output is unchanged: recursive properties use a static `$ref`, and generics produce their default concrete schemas.
