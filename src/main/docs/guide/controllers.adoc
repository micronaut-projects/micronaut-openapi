By default, Micronaut will automatically at compile time build out the Swagger YAML definition from your defined controllers and methods. For example given the following class:

.Hello World Example
snippet::io.micronaut.configuration.openapi.docs.controllers.HelloController[tags="imports,clazz", indent=0, project-base="docs-examples/example", source="main"]

The resulting output will be:

.Example Generated Swagger Output
[source,yaml]
----
openapi: 3.0.1
info:
  title: Hello World
  description: My API
  contact:
    name: Fred
    url: https://gigantic-server.com
    email: Fred@gigagantic-server.com
  license:
    name: Apache 2.0
    url: https://foo.bar
  version: "0.0"
paths:
  /hello/{name}:
    get:
      description: ""
      operationId: index
      parameters:
      - name: name
        in: path
        description: The person's name
        required: true
        schema:
          type: string
      responses:
        200:
          description: The greeting
          content:
            text/plain:
              schema:
                type: string

----

[.lang-java.lang-kotlin]
Notice how the javadoc comments are used to fill out the description of the API.

[.lang-python]
Notice how the docstring of the method is used to fill out the description of the API: it is read like a javadoc comment, so the `@param` and `@return` tags document the parameters and the response.

[.lang-groovy]
Groovy doc comments are not available to the compiler, so the parameter and response descriptions are not generated for Groovy; use the Swagger annotations described in the next section instead.

A controller method parameter which is not sent by the caller is left out of the specification. That is the case for a parameter annotated with `@Hidden` or `@Parameter(hidden = true)`, and for a parameter of a type such as `java.security.Principal`, `io.micronaut.security.authentication.Authentication` or `io.micronaut.http.HttpRequest`.

To leave out every parameter of a type of your own, for example one which is bound from the request by a `TypedRequestArgumentBinder`, list the type in the `micronaut.openapi.ignored-parameter-types` property:

.openapi.properties
[source,properties]
----
micronaut.openapi.ignored-parameter-types=com.example.SignedInUser,com.example.Tenant
----

A parameter is left out if its type is assignable to one of the listed types, so listing an interface covers its implementations.
